# Tracker core: SQLite to Postgres mapping

Migration: `supabase/migrations/20261101000000_tracker_core.sql`. Test: `supabase/tests/database/05_tracker_core.test.sql`.
Item 2 (route inventory) and the later data import reuse this note.

Every table gains `user_id uuid not null default auth.uid()` and RLS limited to the owner. Ids stay `bigint`
(generated by default as identity, so an import can keep the old ids with `overriding system value`).
Parents have `unique (user_id, id)` and children reference `(user_id, parent_id)`.

| SQLite | Postgres | Change |
| --- | --- | --- |
| `companies.name` unique, NOCASE | unique `(user_id, lower(name))` | per user |
| `companies.enriched_on` text, `''` | `date`, null | empty string becomes null |
| `companies.created_at` | new, `timestamptz` | SQLite had none |
| `skills.name` unique, NOCASE | unique `(user_id, lower(name))` | per user |
| `jobs.external_id`, `jobs.code` unique | unique `(user_id, external_id)`, `(user_id, code)` | per user |
| `jobs.created_at` text | `timestamptz` | |
| `jobs.scraped_at` text, `''` | `timestamptz`, null | empty string becomes null |
| `jobs.pay_hourly` 0/1 | `boolean` | |
| `jobs.pay_min_php`, `pay_max_php` | `integer` plus min <= max check | |
| `jobs.posted_on`, `applicants` | still `text` | free text from the posting |
| `jobs.contact_id` | dropped | replaced by `job_contacts` (migration 006 copied the rows) |
| `applications.applied_on` text, `''` | `date`, null | empty string becomes null |
| `applications.job_id` unique | unique `(user_id, job_id)` | |
| `contacts.linkedin_url` unique | unique `(user_id, linkedin_url)` | nulls stay distinct |
| `contacts.company_id` `ON DELETE SET NULL` | `on delete set null (company_id)` | column list keeps `user_id` |
| `contact_log.happened_on` text | `date not null` | |
| `contact_log.follow_up_on` text, `''` | `date`, null | empty string becomes null |
| `contact_log.contact_id`, `job_id` `SET NULL` | `on delete set null (contact_id)` / `(job_id)` | |
| `job_contacts` | same, plus `user_id` | primary key `(job_id, contact_id)` |

Code that compares a date to `''` must test for null instead (`applied_on`, `follow_up_on`, `enriched_on`, `scraped_at`).
